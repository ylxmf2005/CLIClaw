# walkthrough

## 把读者带回能继续判断的位置

先锁定读者真正想理解的对象、实际读取的版本或状态、读者当前认知位置，以及理解之后要作出的判断。默认只假定读者没读过对象，不擅自降低其技术能力；必要概念在首次出现处解释。

Walkthrough 跟着对象的关系走，不按文件、提交或工作阶段复述。先建立理解后续所需的原有情况，再沿入口、关键关系、状态变化和消费者走到结果；没有前后变化的对象，就按目的、组成、约束和待决定处组织。

正文承担理解，链接与证据承担核验。读者不打开源码也应能跟上主线，但每个重要结论都能回到对象、`context.md`、Current Artifacts 或运行证据。图、表、代码块和截图只在明显降低关系、时序或契约的理解成本时使用。

## 让表达边界和证据一致

只展开到读者完成当前判断所需的范围，不把 Walkthrough 做成完整审计。与主线有关的传播关系要讲清；未读取、无证据或刻意排除的部分明确说明，不能因未出现在 diff 里就假定不受影响。

尚未实现、验证不足、存在争议或仍在探索的内容保留真实状态。叙述与现实冲突时修正叙述；需要新调查、用户裁决、实现、测试或独立审查才能成立的结论，交回相应能力，不用确定语气填平。

当前任务有 `context.md`，且讲解需要保存或交接时，写 `<task-workspace>/walkthrough/walkthrough.md`，以 [walkthrough.demo.md](references/templates/walkthrough.demo.md) 为唯一结构来源，并更新 Current Artifacts。否则直接在对话中交付，或使用用户指定路径。

完成时，读者能说清对象是什么、关键关系怎样通向结果、证据支持到哪里、哪些部分未覆盖，以及下一步由谁判断。Walkthrough 不批准方向、实现或交付，也不借讲解扩大对象范围。
