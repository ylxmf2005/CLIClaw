# evolution

## 让这轮代价改变下一轮

从真实任务的输入、判断、行动、失败、纠正和后果出发，寻找会让同类未来工作不同的经验。总结发生过什么不算进化；无法命名未来行为、适用范围和失效条件的观察，也不值得进入长期规则。

先保护当前任务。只有能力缺陷仍在放大当前错误时立即介入，其他发现等到自然停顿或收尾。

## 落到最窄有效来源

当前任务事实与承诺留在 `context.md`；稳定项目事实和决定进入项目规则或文档；重复劳动优先变成结构、检查、测试或工具；只有跨项目可重放的协作机制才修改 Skill。经验保存不取得新的产品范围、长期规则修改权或执行授权，能由系统保证的行为也不只写成更强的提醒。

长期表达提炼可迁移的工作与判断哲学，给真实场景保留必要裁量；只有行为脆弱、可机械判定或一致性本身具有价值时，才固化为清单、穷举或固定步骤。示例会成为强语义锚点，只保留确实希望未来复现的形态；偶然细节、纠正过程和用于证伪的反例留在证据中，不伪装成规范示例。

每类信息只维护一个权威来源：当前状态、专业结论和变化历史分别回到拥有它们的产物，其他位置只引用，不维护平行摘要。来源与权限共同限定修订边界：事实随证据修订，专业结论随对应专业证据修订，用户承诺只随用户的新决定修订；Evolution 记录候选与变化状态，不因此成为这些内容的新权威来源。

Skill 相关误差先区分发现、触发、遵循和正文缺陷，修复实际失效的层。行为性变化读取 [evidence-driven-evolution.md](references/evidence-driven-evolution.md)，用真实轨迹、相邻反例和前后重放判断改善，并让用户批准具体范围或 diff；链接、格式、历史状态和 UI 元数据等机械维护用静态证据。

更新长期能力时检查相邻 Skill 的触发与职责，删除被替代的旧规则，不用新旧两套表达同时支配未来。

## 分清结论与中间状态

Evolution 只以三种结论收敛：

1. **无可复用经验**：证据只属于当前任务，或不会改变未来行为。说明判断即可，不创建文件。
2. **候选待授权**：经验与最窄落点已经成立，但用户尚未批准具体变化。需要交接时保存候选，不提前修改长期来源。
3. **已验证变化**：用户已授权，变化已落到权威来源，并由与变化类型相称的前后证据证明。只有这时才能称为改善。

已经修改但尚未验证，是必须公开的中间状态，不是改善结论。继续取得证据；若外部阻塞迫使交接，就如实标为“已修改待验证”，不能降格伪装成候选，也不能写成已改善。

任务内的候选、待验证修改或已验证变化需要保存时，写 `<task-workspace>/evolution/evolution.md`，以 [evolution.demo.md](references/templates/evolution.demo.md) 为唯一结构来源；只有行为重放或独立核验需要时才建立 `evals/` 与 `evidence/`。存在 `context.md` 时更新 Current Artifacts；没有所属任务时在对话中交付，或使用用户指定路径，不假定 `studio/` 目录。

Evolution 只决定经验怎样改变未来，不借复盘重新打开已经完成的产品范围。
